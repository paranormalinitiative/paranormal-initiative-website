# TPI DEVELOPMENT STANDARD
## MANDATORY MARKDOWN DOCUMENTATION SYNCHRONIZATION

**Applies to:** Every development directive, correction, addendum, deployment, and completed implementation across The Paranormal Initiative and StudioFlow.

### 1. COMPLETE MARKDOWN DOCUMENTATION REVIEW

Before beginning development, the assigned agent must inventory and review all `.md` files within the applicable project's development documentation system.

This includes governing instructions, architecture, directives, indexes, implementation records, workflows, testing procedures, deployment records, and agent handoff documentation.

Do not assume the documentation is limited to files explicitly named in the directive.

### 2. MANDATORY SYNCHRONIZATION

After implementation, the agent must evaluate every Markdown file in the applicable documentation system for accuracy against the completed changes.

**Every affected `.md` file must be updated.**

Files that remain accurate must be preserved without unnecessary modifications.

No affected document may retain outdated instructions, incorrect implementation descriptions, obsolete file references, or conflicting development status.

### 3. SINGLE AUTHORITATIVE DEVELOPMENT TRUTH

All current-state Markdown documentation must agree on:

- Implemented functionality.
- System architecture.
- Source file locations.
- Configuration and persistence.
- Development status.
- Outstanding work.
- Testing and verification.
- Deployment status.
- Known limitations.

Historical records must remain intact and clearly distinguish previous behavior from current behavior.

### 4. AGENT-INDEPENDENT CONTINUITY

A new development agent must be able to understand the project using the repository and Markdown documentation alone.

No agent may rely on private conversation history or undocumented decisions.

### 5. DOCUMENTATION COMPLETION GATE

Before declaring a directive complete, the agent must:

1. Inventory the applicable Markdown documentation.
2. Identify all files affected by the implementation.
3. Update every affected file.
4. Check for contradictions between documents.
5. Verify that directive indexes and development status records are current.
6. Update architecture, workflow, and testing documentation where necessary.
7. Create the required dated completion record.
8. Commit and push documentation changes.
9. Report which Markdown files were updated.
10. Confirm that the remaining Markdown files were reviewed and require no changes.

### 6. FINAL REQUIREMENT

**A development directive is not complete if its implementation is correct but its Markdown documentation is incomplete, outdated, or contradictory.**

The project must be understandable to any qualified development agent without requiring access to previous conversations.

**END OF STANDARD**
