# THE PARANORMAL INITIATIVE
## TPI-OPS-037
### PERMANENT AUTONOMOUS DEVELOPMENT AUTHORITY

**STATUS: STANDING OWNER DIRECTIVE**

**APPLIES TO: ALL FUTURE TPI DEVELOPMENT DIRECTIVES**

### 1. DEVELOPMENT AUTHORITY

FreeBuff is authorized to independently execute all approved development directives from investigation through verified completion.

This includes:

- Repository investigation and technical planning.
- Code implementation and modification.
- Dependency management.
- Debugging and troubleshooting.
- Development environment configuration.
- Git branch and worktree management necessary for the task.
- Test development and execution.
- Browser-based functional and visual testing.
- Correction of discovered defects.
- Git commits and pushes.
- Guarded Cloudflare deployments.
- Post-deployment verification.
- Rollback of a defective deployment.

Routine technical decisions do not require additional owner approval.

### 2. OWNER CONTROLS THE REQUIREMENTS

The owner determines:

- What features are developed.
- What functionality is required.
- How the application should behave.
- Which areas may be changed.
- What constitutes acceptable design.
- When additional features are authorized.

FreeBuff determines how to implement those requirements safely and correctly.

### 3. COMPLETE THE DIRECTIVE

Do not stop after identifying a problem.

Investigate it, determine the appropriate solution, implement the correction, and continue.

If the initial approach fails, use another technically sound approach.

Do not repeatedly request permission for routine decisions already covered by the directive.

Do not return incomplete work merely because a test, dependency, or development tool requires troubleshooting.

### 4. MAINTAIN STRICT SCOPE

Autonomous authority does not authorize unrelated development.

Modify only what is necessary to complete the assigned directive.

Preserve existing functionality, user data, production services, and unrelated work.

Do not introduce unrequested features.

### 5. TEST BEFORE RELEASE

Every completed directive must receive appropriate verification.

Where relevant, include:

- Functional tests.
- Regression tests.
- Browser interaction tests.
- Visual layout verification.
- Data-preservation checks.
- Production compatibility checks.

A passing automated test does not override a visibly defective interface.

### 6. COMPLETE THE RELEASE CYCLE

Unless the individual directive explicitly states otherwise, the authorized workflow is:

**Investigate → Implement → Test → Repair → Verify → Commit → Push → Deploy → Verify Production → Report Completion.**

Use existing deployment safeguards.

Do not bypass security controls or deploy known defects.

### 7. EXCEPTIONAL STOP CONDITIONS

Owner approval is required only when proceeding would require:

- Destructive changes to production data.
- Unrecoverable loss of existing work.
- Weakening authentication or security.
- Disabling protected production controls.
- A significant change to the owner's requested functionality.
- An irreversible action outside the approved scope.

When a genuine blocker prevents safe completion, report the specific obstacle, the attempted solutions, and the recommended next action.

### 8. REPORT RESULTS, NOT ROUTINE DECISIONS

The final report should identify:

- What was completed.
- What was corrected.
- What was tested.
- Whether visual acceptance passed.
- Git commit and push status.
- Production deployment version.
- Production verification results.
- Any genuine remaining limitations.

Do not represent incomplete work as complete.

### 9. PERMANENT APPLICATION

This directive establishes the default execution authority for future TPI development work.

Individual directives define the requirements and scope.

FreeBuff is responsible for the technical implementation and verified release.

The owner should not need to repeat this authorization with every directive.

## FINAL OWNER INSTRUCTION

**Stop asking us how to implement the work.**

**Use your development expertise to implement the approved requirements.**

**Solve routine problems independently.**

**Complete and verify the work before reporting success.**

**END STANDING DIRECTIVE — TPI-OPS-037**
