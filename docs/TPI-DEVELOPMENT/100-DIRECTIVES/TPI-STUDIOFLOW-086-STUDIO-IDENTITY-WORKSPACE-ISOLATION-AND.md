====================================================================
THE PARANORMAL INITIATIVE
DIRECTIVE TPI-STUDIOFLOW-086
STUDIO IDENTITY, WORKSPACE ISOLATION, AND DIRECTIVE RECONCILIATION
====================================================================

PRIORITY: CRITICAL
STATUS: AUTHORIZED FOR INVESTIGATION

PRODUCTION:
https://paranormalinitiative.com/studio/

PRIMARY BROWSER:
Firefox Developer Edition

====================================================================
1. STOP WORKSPACE MUTATIONS
====================================================================

The owner reports that StudioFlow is displaying the name
"Crossroads of the Unknown" while showing an unexpected
workspace.

The owner also reports:

- The existing motion background is no longer displayed.
- Crossroads is missing from the My Studios dropdown.
- The editor appears to be loading the wrong studio.
- Previous repairs have not preserved the complete
  intended multi-studio behavior.

Until the cause is established:

DO NOT:

- Create or delete studios.
- Rename Crossroads.
- Replace backgrounds.
- Reset workspaces.
- Clear browser storage.
- Import or restore backups.
- Run migrations.
- Perform destructive media operations.
- Write synthetic data into owner studios.

Preserve all current owner data.

====================================================================
2. RECONCILE THE ORIGINAL DIRECTIVES
====================================================================

Review the master chronological directive register.

Review the original StudioFlow directives, their amendments,
implementation reports, and current production behavior.

Determine the authoritative requirements for:

- Studio creation.
- Blank workspace initialization.
- Unique studio identities.
- My Studios registration.
- Studio switching.
- Workspace isolation.
- Scene persistence.
- Background persistence.
- Media ownership.
- Browser-local and server-backed storage.
- Workspace restoration.

Do not assume that a previously marked COMPLETE directive
still behaves correctly.

Identify where current implementation diverges from the
original requirements.

====================================================================
3. INVESTIGATE CROSSROADS IDENTITY
====================================================================

Using read-only diagnostics, identify:

A. The studio name displayed in the editor.

B. The actual active studio ID.

C. The workspace ID used to load scenes.

D. The studio ID used for autosave.

E. The studio ID associated with the visible background.

F. The studio registry used by My Studios.

G. Whether Crossroads exists in browser-local storage.

H. Whether Crossroads exists in server-backed records.

I. Whether multiple Crossroads workspaces exist.

J. Whether a studio-name/workspace-ID mismatch exists.

K. Whether the expected motion background still exists
   in stored scene or media records.

Do not infer studio identity from its displayed name.

Use actual persisted identifiers.

Do not expose sensitive owner data in public logs.

====================================================================
4. DETERMINE WHAT HAPPENED TO THE BACKGROUND
====================================================================

Investigate whether the missing motion background was:

- Replaced in the stored scene.
- Removed from the scene assignment.
- Hidden by incorrect workspace hydration.
- Associated with a different studio.
- Still present in media storage.
- Affected by the latest production deployment.

Do not overwrite or delete anything during investigation.

Report whether the original background is recoverable.

====================================================================
5. VERIFY MY STUDIOS
====================================================================

Determine why Crossroads is absent from My Studios.

Check whether the dropdown is:

- Reading an incomplete registry.
- Using the wrong browser storage.
- Filtering valid studios.
- Failing to synchronize server-backed studios.
- Displaying stale data.
- Using a different studio identity source.

Identify the authoritative studio registry.

Do not create duplicate studios to conceal the problem.

====================================================================
6. RESTORE ORIGINAL MULTI-STUDIO BEHAVIOR
====================================================================

Once the cause is established, prepare the smallest
safe repair.

Required behavior:

Every newly created studio receives:

- A unique immutable studio ID.
- An independent blank workspace.
- Independent scenes.
- Independent media assignments.
- Independent saved state.
- A persistent My Studios entry.

Selecting a studio must:

1. Save the current studio.
2. Preserve its scenes and media assignments.
3. Switch the active studio ID.
4. Load the selected studio's workspace.
5. Update the displayed studio name.
6. Restore its exact saved state.

Never reuse another studio's workspace simply because
the displayed name matches.

Never silently replace existing scene content.

====================================================================
7. SAFE TESTING
====================================================================

Perform mutation testing only with disposable studios.

Do not use Crossroads for destructive testing.

Verify:

- New studio starts blank.
- New studio appears in My Studios.
- Existing studios remain listed.
- Each studio has a different ID.
- Studio A and B retain independent scenes.
- Studio A and B retain independent backgrounds.
- Switching studios restores the correct workspace.
- Refreshing preserves studio identity.
- Reopening restores the correct studio.
- Deleting a disposable studio does not affect others.

Include checks for browser-local and server-backed
state consistency.

====================================================================
8. PRODUCTION REPAIR
====================================================================

Do not deploy a repair until the owner-data risk has
been assessed.

If the repair can be safely applied without altering
Crossroads data, implement and verify it.

If owner data must be changed, stop and report the
specific proposed changes for owner approval.

Use the established guarded production deployment process.

I. REPAIRS IMPLEMENTED
J. PRODUCTION ACCEPTANCE RESULTS
K. REMAINING DIRECTIVE GAPS
L. FINAL STATUS

====================================================================
FINAL ORDER
====================================================================

DO NOT TREAT THIS AS AN ISOLATED DROPDOWN BUG.

RECONCILE THE COMPLETE MULTI-STUDIO DESIGN.

ESTABLISH WHICH WORKSPACE IS ACTUALLY BEING DISPLAYED.

PROTECT THE ORIGINAL CROSSROADS CONTENT.

RESTORE THE REQUIRED STUDIO IDENTITY AND ISOLATION.

DO NOT DECLARE COMPLETE UNTIL LIVE BEHAVIOR MATCHES
THE ORIGINAL DIRECTIVES.
