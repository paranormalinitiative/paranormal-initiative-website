====================================================================
THE PARANORMAL INITIATIVE
DIRECTIVE TPI-MASTER-001B
MANDATORY COMPLETION AND NO-PARTIAL-DELIVERY POLICY
====================================================================

STATUS: AUTHORIZED
PRIORITY: CRITICAL
APPLIES TO: ALL CURRENT AND FUTURE TPI DIRECTIVES
SUPERSEDES: ANY PREVIOUS STOP-AT-PARTIAL WORKFLOW

====================================================================
1. PRIMARY ORDER
====================================================================

CODEX MUST FINISH WHAT IT STARTS.

Effective immediately, all TPI directives must be executed
through full implementation, testing, deployment, and
production verification.

A directive is not complete simply because:

- Code was written.
- Files were modified.
- A deployment succeeded.
- Automated tests passed.
- An investigation was completed.
- Documentation was updated.
- A problem was partially repaired.

The objective is WORKING PRODUCTION FUNCTIONALITY.

====================================================================
2. NO MORE PARTIAL COMPLETION REPORTS
====================================================================

Do not voluntarily stop work and return a PARTIAL result
when additional authorized work can resolve the issue.

If a test fails, investigate and repair the failure.

If browser automation times out, diagnose the timeout and
use an alternative testing method.

If a deployment reveals another defect, repair that defect.

If an integration is incomplete, finish the integration.

If a requirement is missing, implement it.

If a regression is introduced, resolve it before completion.

Continue working until the directive's acceptance criteria
are satisfied.

Do not use a documentation update as a substitute for
finishing implementation.

====================================================================
3. ONE DIRECTIVE AT A TIME
====================================================================

Follow the historical Master Directive Register in
chronological order.

For each directive:

1. Read the complete original requirements.
2. Identify subsequent corrections and amendments.
3. Inspect the existing production website.
4. Implement missing functionality.
5. Repair existing defects.
6. Run required tests.
7. Deploy reviewed, non-destructive changes.
8. Verify actual production behavior.
9. Resolve all failures within the directive's scope.
10. Record completion.
11. Proceed to the next directive.

DO NOT begin the next directive while the current directive
has unresolved, actionable requirements.

====================================================================
4. PRODUCTION VERIFICATION IS MANDATORY
====================================================================

Every implemented directive must be verified against the
actual live Paranormal Initiative website.

Local testing alone is insufficient.

Source-code inspection alone is insufficient.

Successful deployment alone is insufficient.

A functioning API does not automatically prove that the
corresponding browser interface works.

Verify the complete user-facing workflow wherever applicable.

For StudioFlow, this includes actual authenticated editor
behavior, saving, switching, persistence, and restoration.

If browser automation fails, investigate the cause and
attempt alternative reliable verification methods.

Do not declare completion based on assumptions.

====================================================================
5. AUTOMATIC PROBLEM RESOLUTION
====================================================================

Codex is authorized to investigate and resolve ordinary
technical problems encountered while completing a directive.

Do not repeatedly request permission for:

- Routine code corrections.
- Non-destructive integration repairs.
- Test failures.
- Browser automation troubleshooting.
- JavaScript errors.
- Styling defects.
- Broken internal navigation.
- API integration defects.
- Configuration errors within existing approved systems.
- Non-destructive deployment corrections.

Continue working through these problems using the
existing approved production workflow.

Do not abandon a directive because the first solution
does not work.

====================================================================
6. EXCEPTIONS REQUIRING OWNER AUTHORIZATION
====================================================================

Do not bypass security controls or perform destructive
operations to satisfy this completion policy.

Explicit approval is still required for:

- Deleting or overwriting production owner data.
- Resetting production databases.
- Destructive schema changes.
- Deleting existing studios or recordings.
- Initiating public broadcasts.
- Purchasing paid services.
- Changing ownership or access permissions.
- Operations that create material risk to production data.

If completion genuinely requires one of these actions,
document the exact requirement and request authorization.

Do not falsely report completion.

A genuine external blocker must be reported accurately,
including the work needed to resolve it.

====================================================================
7. NO UNNECESSARY INTERRUPTION
====================================================================

Do not interrupt execution simply to announce:

- Investigation complete.
- Files updated.
- Tests partially passed.
- Deployment complete.
- Browser automation unavailable.
- Further verification recommended.

These are intermediate milestones, not final outcomes.

Record intermediate progress in the execution log and
continue working.

Return a completion report when the directive has been
fully implemented and verified.

If a genuine authorization or external dependency blocker
prevents completion, report that blocker rather than
misrepresenting the work as finished.

====================================================================
8. COMPLETION STATUS
====================================================================

The preferred final status is:

COMPLETE — PRODUCTION VERIFIED

This status requires:

- All applicable requirements implemented.
- All required tests passed.
- Production deployment confirmed.
- Actual live functionality verified.
- No unresolved defects within the directive's scope.
- Existing functionality preserved.
- Documentation updated.

SUPERSEDED may be used when a later approved directive
replaces the original requirement.

BLOCKED — OWNER ACTION REQUIRED may be used only when
completion genuinely cannot proceed without authorization,
credentials, or an external dependency.

Do not use PARTIAL as a convenient stopping point.

Never substitute an inaccurate COMPLETE status for a
genuinely unfinished directive.

====================================================================
9. EXISTING UNFINISHED WORK
====================================================================

Review existing directives previously reported as PARTIAL.

Identify their unfinished requirements.

When those requirements are reached in the chronological
execution sequence, complete them before advancing.

Do not duplicate working functionality.

Do not repeat completed work unnecessarily.

Preserve all production data and existing functionality.

====================================================================
10. FINAL EXECUTION ORDER
====================================================================

START THE DIRECTIVE.

IMPLEMENT THE REQUIREMENTS.

TEST THE FUNCTIONALITY.

FIX THE FAILURES.

DEPLOY SAFELY.

VERIFY THE LIVE WEBSITE.

FINISH THE DIRECTIVE.

DOCUMENT COMPLETION.

MOVE TO THE NEXT DIRECTIVE.

REPEAT UNTIL THE ENTIRE MASTER DIRECTIVE REGISTER
HAS BEEN PROCESSED.

====================================================================
FINAL MANDATE
====================================================================

THE PARANORMAL INITIATIVE DOES NOT CONSIDER A DIRECTIVE
FINISHED UNTIL ITS REQUIRED FUNCTIONALITY IS WORKING
AND VERIFIED ON THE PRODUCTION WEBSITE.

DO NOT STOP AT THE FIRST OBSTACLE.

DO NOT STOP AFTER DEPLOYMENT.

DO NOT STOP AFTER AN INVESTIGATION.

DO NOT STOP BECAUSE ONE TESTING METHOD FAILS.

SOLVE THE PROBLEM AND COMPLETE THE WORK.

FINISH WHAT YOU START.

====================================================================
END DIRECTIVE TPI-MASTER-001B
