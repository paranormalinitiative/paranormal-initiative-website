# TPI-OPS-014 — Automatic Local Server Startup

## Directive status

TPI-OPS-014 converts the existing local TPI Worker launcher into a
user-level macOS `launchd` service. It does not create a new Worker, replace
the existing local runtime, control the StudioFlow room server, deploy code,
or contact a hosted TPI environment.

The implementation is local-only and preserves the existing `npm run
dev:local` launcher as the source of Worker startup behavior.

## Service contract

- Label: `com.tpi.local-development`
- Plist: `/Users/toddknipple/Library/LaunchAgents/com.tpi.local-development.plist`
- Repository: `/Users/toddknipple/Documents/GitHub/paranormal-initiative-website`
- Worker URL: `http://127.0.0.1:8787/`
- Preserved StudioFlow room server: `http://127.0.0.1:8788/`
- Launch executable: the current absolute Node executable at install time
- Wrangler executable: `/opt/homebrew/bin/wrangler`
- Launch behavior: `RunAtLoad`, `KeepAlive`, `ThrottleInterval=10`
- Environment: `TPI_ENV=local`, loopback-only, outbound services disabled

The installed plist is owned and generated by `scripts/local-dev-service.mjs`.
It contains no API keys, credentials, session tokens, or hosted TPI targets.
The service log is `.local-dev/logs/local-development.log`, with a 2 MiB
current-file limit and one rotated file. The service log is mode `0600`.

## Owner controls

The service control surface is explicit and owner-gated:

```sh
TPI_LOCAL_OWNER_CONTROL=1 npm run dev:local:service:install
TPI_LOCAL_OWNER_CONTROL=1 npm run dev:local:service:start
TPI_LOCAL_OWNER_CONTROL=1 npm run dev:local:service:stop
TPI_LOCAL_OWNER_CONTROL=1 npm run dev:local:service:restart
npm run dev:local:service:status
TPI_LOCAL_OWNER_CONTROL=1 npm run dev:local:service:uninstall
```

The generic `npm run dev:local:stop` command refuses to stop an owner-managed
Worker unless the explicit owner-control variable is present. Intentional
service stop uses `launchctl bootout` and does not immediately restart. The
owner must start or restart the service explicitly afterward.

`TPI Local Development.command` is a Finder-friendly owner launcher. It sets
the owner-control variable internally, starts the service, waits for the
loopback health check, and opens the local URL. Finder may briefly open a
Terminal window while the command runs.

## Safety boundaries

The service binds only to loopback and uses `wrangler.local.toml` plus the
secret-free `scripts/local-dev.env`. It does not deploy, import D1/R2 data,
modify production or hosted development, or control port 8788. Existing local
D1/R2 state remains under `.local-dev/state`.

The wrapper records only bounded, redacted process output. It does not log
credentials or private environment values. The local launcher parent monitor
terminates the child Worker if the service wrapper unexpectedly disappears,
preventing an orphaned Worker from surviving an owner-controlled service
failure.
