## 3. Third-party, font and asset license boundary

- **NOTICE obligations:** The root `NOTICE` states that bundled third-party components are listed in `THIRD-PARTY-NOTICES.txt`. That file is generated by `tools/gen-third-party-notices.mjs` at packaging time and is **not checked in**. Nova would need to generate or author its own equivalent.
- **Bundled fonts:** Documented in `apps/docs/src/renderer/fonts/README.md`:
  - Carlito, Liberation (Serif, Sans, Mono), Aptos GO family, Century Gothic GO: SIL OFL 1.1 (`LICENSE-OFL.txt`).
  - Caladea, Cambria Math GO, Bookman Old Style GO: Apache-2.0.
  - OFL families require their license text and copyright notices to travel with the font files.
- **Downloadable-font catalogue:** `packages/electron-utils/src/font-catalog.ts` lists downloadable families (SIL OFL 1.1). This is a desktop mechanism (see section 8) and is not on the Nova path.
- **Icons:** `apps/docs/src/renderer/components/icons.tsx` and `table-icons.tsx` are generated monochrome SVG components. `ribbon-tabs.tsx` also imports two PNG assets (`icon-editor.png`, `icon-translate.png`). Their origin and license are **not yet verified**; they must be verified before any reuse.
- **Branding:** GenOffice/Genspark branding must not be imported. The icon set is described in code as "approximating Word's ribbon glyphs"; that is a visual reference, not a licensing grant.

## 8. Home, Draw, Review and View structure

**Home** is implemented inline in `Ribbon.tsx`, not in a separate tab file. Its functional groups are Clipboard, Font, Paragraph and Styles. Structural and command dependencies:
- Format state from `ribbon-format-state.ts` (`DocDefaults`, `Run`, `StyleInfo` types).
- Direct editor commands in `Ribbon.tsx` (12 `chain` calls, 11 dispatch calls).
- AI buttons Summarize, Polish and Tidy are passed in as host props (`onAiPreset`); they are not direct calls from the ribbon.
- `document.execCommand(action)` at `Ribbon.tsx:2236` (browser-native command path).

The full Home capability matrix is for 005B0B.

**Draw** (`DrawTab`, `ribbon-tabs.tsx` ~1721): ink and shape drawing. Imports editor modules `ink` and `shape-draw`, and uses docx-engine runtime XML builders (`buildLineParagraphXml`, `buildShapeParagraphXml`, `buildTextboxParagraphXml`, `buildWordArtParagraphXml`).

**Review** (`ReviewTab`, `ribbon-tabs.tsx` ~824): comments and track-changes controls. Imports `../editor/revision-filters` and reads revision state from the editor.

**View** (`ViewTab`, `ribbon-tabs.tsx` ~1389): zoom, layout and window controls. Uses desktop window APIs (`window.desktop.listDocsTabs`, `openNewTab`, `focusDocsTab`) for multi-document tabs.

## 14. File tab and application-shell boundary

**Professional document commands Nova may want (candidates to re-express through TPI export/save APIs):** Save/Save As semantics as a concept, print, and export formats. Nova already owns save through its storage layer; these are not adopted as GenOffice shell behavior.

**GenOffice desktop shell behavior (not ported):** native file open/save dialogs, multi-document tabs (`listDocsTabs`, `openNewTab`, `focusDocsTab`), native application menus (File tab is omitted on Mac), window management, and recent-file handling.

The File dropdown in `Ribbon.tsx` is driven entirely by host callbacks, so the ribbon itself does not own file I/O. The shell remains outside the adoption.

## 15. Initial A/B/C/D classification

Key: **A** directly reusable/adaptable · **B** reusable with Nova adapter · **C** architectural reference / too coupled · **D** excluded.

| Module | Class | Reason |
|---|---|---|
| `Ribbon.tsx` | C | Composes all tabs, File/Home inline, AI host props and ~24 direct editor calls; too coupled to adopt as-is; use as composition reference |
| `ribbon-tabs.tsx` | C | Hosts Draw, Review, View and Translate; uses desktop tab APIs, `runUiOps`, `window.confirm`, and XML builders; needs splitting before any use |
| `ribbon-format-state.ts` | B | Pure selection/format derivation over ProseMirror state; reusable with a Nova selection adapter (TipTap) |
| `ribbon-color-palette.tsx` | A | Small presentational component over `ColorPicker`; no desktop or AI coupling |
| `ribbon-insert-tab.tsx` | B | Presentational, but depends on docx-engine chart types and WordArt presets; needs adapter for shapes and charts |
| `ribbon-design-tab.tsx` | B | Presentational; depends on document defaults/style types; reusable behind a Nova style adapter |
| `ribbon-layout-tab.tsx` | B | Presentational; editor-internal module coupling (~several modules) must be adapted |
| `ribbon-references-tab.tsx` | D (Zotero, citation IPC) / C (field XML) | Zotero IPC is excluded; DOCX field generators are a schema decision for later |
| `ribbon-mailings-tab.tsx` | B | Small; `mergeFieldInstruction` is a generic utility; merge data source must be replaced with a Nova type |
| `ribbon-hf-tab.tsx` | C | Depends on a header/footer editing model not present in Nova |

AI-related controls (Translate, Summarize, Polish, Tidy, Name with AI) are **D** by the Nova exclusion rule and are not reused even where the surrounding module is B or C. Electron/IPC paths are **D**.

## 16. Command boundary

| Category | Current GenOffice mechanism | Redirectable to a Nova command layer? |
|---|---|---|
| Direct editor chains | `editor.chain()` in `Ribbon.tsx` (12) and `ribbon-tabs.tsx` (13), `ribbon-insert-tab.tsx` (7), `ribbon-layout-tab.tsx` (2), `ribbon-references-tab.tsx` (7) | Yes, if wrapped as commands that return a ProseMirror transaction intent |
| Dispatch | `dispatch` calls in `Ribbon.tsx` (11), `ribbon-tabs.tsx` (3), `ribbon-insert-tab.tsx` (2) | Yes, in the same wrapper |
| Utility/XML builders | docx-engine functions | Yes, as pure functions called from the command layer |
| Editor modules | `../editor/*` helpers (~30 imports) | Partially; each needs an adapter |
| AI ops | `runUiOps` | Excluded |
| Host callbacks | `onAiPreset`, `onNameWithAi`, Open/Save | Replaced by Nova host; storage stays outside |

The ribbon UI currently mixes command execution with presentation. A Nova command layer would take the chain/dispatch calls; the ribbon would only emit command identifiers.

## 17. No storage porting

GenOffice ribbon and editor UI adoption must **not** take ownership of: Nova autosave, Nova revisions, `expectedVersion`, article metadata, publication, or editorial workflow. These remain TPI/Nova responsibilities. The ribbon command layer ends at editor/document state mutation. Storage stays outside.
